Embedded systems · C# / .NET · Firmware update · UDP

Field firmware update for networked devices

Extended a Windows maintenance tool for networked embedded devices, so that site staff can update firmware and configure devices over the network instead of visiting each one. I designed every change against the device firmware and hardware it drives.

  • Added network firmware update for several device variants on two processor families, reporting exactly which devices failed so none is left on old firmware unnoticed.
  • Studied the device firmware on both processor families to choose the update method and reused the proven production loader instead of maintaining a second one.
  • Proved that an interrupted update cannot leave a device unusable, by cutting power and pulling the network cable mid-transfer on every hardware type.
  • Extended an existing device protocol with new settings without adding commands, keeping it backward compatible with devices already installed and agreed the changes with the firmware developer.
  • Root-caused configuration bugs from packet captures and the device firmware and verified each fix on the device across a power cycle.
  • Wrote the illustrated update manual for site staff.

Ethernet failure investigation and production quality

Led the investigation of a batch failure across hundreds of networked embedded controllers, made a design change to a released product, and took over fault-finding, test and release of two embedded products in the security sector.

  • Traced a network failure affecting 300+ units to counterfeit components, by isolating the fault to one subsystem and then eliminating every other cause by measurement against a known-good board.
  • Reported the finding to procurement and management, reworked the first batch of boards myself by fine-pitch hot-air rework, then trained the workshop on the method and inspected their work.
  • Diagnosed an output stage that could not drive a customer's new load, and specified a component change that went into the bill of materials and the schematic for all future production.
  • Ended a production stoppage caused by unreliable test equipment: found intermittent wiring and contact faults, rebuilt the jig to its documentation and replaced worn contacts. False failures dropped to zero, revealing the real defects they had been hiding.
  • Repaired multiple returned units at component level from the schematics, covering power and protection circuits, isolated outputs, audio stages and microcontrollers.
  • Held sign-out authority as QA: every unit leaving the workshop needed my release.

Door controller firmware

Sole firmware engineer for a networked access-control door controller, which is commanded at the same time by an industrial control system, PC software, card readers and a mobile app. I owned new features, field fault investigation and releases.

  • Worked on a multi-task FreeRTOS design on an STM32 Cortex-M4, with interrupt-driven peripherals and state machines.
  • Added a new door type end to end, from requirements to on-site release, without a hardware change.
  • Recreated the customer's industrial network on the bench and made it a pass/fail gate for every release.
  • Reproduced and fixed long-standing intermittent field faults by building test rigs that triggered them on demand, including a race condition between concurrent inputs.
  • Replaced fragile flag-based sequencing with timer-driven logic that always recovers and added safe fallbacks for invalid stored settings.
  • Debugged on target over SWD with breakpoints and live variable watch and verified fieldbus traffic with a CAN analyser.

Embedded systems · C# / .NET · MySQL · UDP / TCP

Multi-user control and alarm software for networked devices

Turned a single-user Windows tool for networked embedded controllers into a server and client system for several control-room operators. I also extended a service that forwards device events to an alarm monitoring platform. I designed every change around the controllers' protocol and firmware behaviour.

  • Built one application that runs as server, operator client or on-site technician tool. Every instance talks to the controllers directly over UDP, so operating a device never depends on the server being up.
  • Kept the software usable when the database is offline by falling back to a local device list, and showed server health to operators through a database heartbeat.
  • Moved device event logging onto a background worker thread, so database delays never block the interface or incoming device traffic.
  • Added role-based access control with encrypted credentials and produced dated PDF incident reports from the event log.
  • Added offline detection and per-device, per-event rate limiting to the alarm link, so one faulty device cannot flood the control room or hide real alarms.
  • Debugged device traffic with packet captures and UDP/TCP terminals, verified every release on a hardware test rig and commissioned the alarm link on site with the operators' security team using a TCP test harness I built.
  • Automated the manual hardware test procedure as a guided test page, cutting my own test time per unit from about 20 minutes to under 5 minutes.

Project ownership · Manufacturing systems · Dolibarr ERP · C# / .NET · MySQL

Leading the replacement of a production-critical ordering process

Took ownership of the move from a single-user spreadsheet, which every component order for printed circuit board assembly production depended on, to two multi-user applications integrated with the company's Enterprise Resource Planning. With no specification, plan or team handed to me, I defined the scope, engaged the people affected, managed the risk to a live business process and made the decision to switch over.

  • Set the objective and the acceptance criterion: no live order would go through the new system until its results matched the trusted spreadsheet's.
  • Brought together the needs of procurement, engineering, the workshop, the assembly manager, the office and the outside assembly house, each with its own requirements and its own level of access.
  • Ran the work as staged releases, one functional area at a time. I kept one fault and change list for all users and prioritised it by impact on production, so anything that stopped ordering always came first.
  • Kept a risk register with a control for each risk: a side-by-side run against the spreadsheet, a staging copy of the database, a fallback to the old process until acceptance, least-privilege access, and approval before writing to the ERP.
  • Extended the shared database without breaking other tools that depend on it, and kept ordering and production tracking running through the company's DataBase upgrades.
  • Rebuilt and verified the material requirements calculation, corrected the stock model and traced and fixed my own errors before they reached a live order.
  • Led acceptance testing with the main user and made the cutover decision. The spreadsheet is retired, ordering is no longer limited to one person, the workshop and engineers have live visibility of jobs and stock, and BOM capture has dropped from about 7 to about 2 minutes by the procurement manager's estimate.
